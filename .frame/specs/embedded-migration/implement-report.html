What changed

Added eight migration events to the activity registry (detected, deferred, skipped, artifact, restored, posture, completed, failed) with their enums exported for the engine to reuse, plus a `migration_failed` telemetry event, a `bucketCount` helper, and the matching PRIVACY.md row. Tests cover both registries.

Why

The dispositions are exported as MIGRATION_DISPOSITIONS so plan() can label artifacts with the same strings the log records — one vocabulary, not two that can drift. Telemetry counts are bucketed ranges because that registry is enum-only by construction; the exact numbers stay in the local activity log.
