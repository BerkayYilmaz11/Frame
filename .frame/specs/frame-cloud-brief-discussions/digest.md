Frame is where a Frame Cloud proposal is talked over and decided: Discuss opens a lane with the default AI tool, the agent records settled points on the user's yes (`brief.recordDiscussion`), and Move to Work (`brief.decide`, with a priority) turns it into work. Writes allowed: recordDiscussion, decide, and addAttachment for a write-up link only — never `brief.update`; the description stays the user's.
Record path: main issues a 24-hex discussion id (persisted 90 days in `<userData>/cloud-discussions/discussions.json`), stages `record-discussion.js` beside a file bus in userData (nothing in the user's repo); the command sends only id + summary (stdin heredoc) + optional http(s) url. Bus: tmp + rename; main claims by rename to `.taken` and answers in `replies/`; the command waits 30 s, withdraws on timeout and says "did not answer" only if the withdrawal succeeded; stale requests are dropped, not recorded. Rejected: env-var bus, in-memory ids, summary as an argument, token/brief id in the terminal.
`call()` folds server codes (NOT_A_PROPOSAL, ALREADY_CLOSED, ALREADY_WORK) into badRequest, so record and decide catch them inside the called function and return them as values.
The prompt travels as a file (`<userData>/cloud-discussions/prompts/<id>.md`), the lane gets one "Read '<path>' and follow it exactly" line — typing a long prompt got cut by Claude Code's paste handling and lost the record command. Rule: never type a long prompt into a lane.
Prompt content: brief, links, records and comments fenced as data; only fate-deciding questions stay open, details "can wait"; Claude Code asks at wrap-up to publish a claude.ai artifact; Codex gets no document offer; never a local file; with new comments it opens on them (Re-discuss is a plain Discuss).
States (pure `proposalStage`, shared by card and detail): no record → Discuss · lane open → Discussing in <lane> · ≥1 record → Move to Work + Discuss · others' comments after the latest record → "N new comments" chip → Comments tab with Re-discuss. Counts come from `brief.events` per open proposal (rejected: a FrameCloud list field, a local counter); own comments never count as new.
A record's write-up link is also added to Links ("Discussion write-up (<date>)"); Discussions then says "Write-up added to Links", older records keep their link. Lanes carry `assignment.kind: 'brief'` (current-project lookup); the chip opens the brief. Cards are containers — never nest controls in the card button.
Open: the heredoc assumes a POSIX shell (Windows PowerShell lanes); per-proposal events requests could become one `discussionCount` on `brief.list`; the web still shows the write-up link inside its Discussions section.

Chain: spec.md → plan.md → tasks.md → outcome.md
