The status bar's branch label became a button that opens a VS Code-style branch picker above it: filter focused on open, local branches first (current pinned, then newest commit), remote branches without a local twin under a divider, "Create new branch '<text>'" from the filter on top, "Manage branches…" at the bottom handing off to the GitHub view's Branches section. Eight tasks, eight commits on `feat/status-bar-branch-picker`, `npm test` 724 pass.
Shape: `src/renderer/statusBar/branchPickerModel.js` (pure: grouping, remote dedupe on `shortName`, ordering, filter, worktree disabling, create-row states, keyboard order — 17 tests) under `branchPicker.js` (DOM host: parallel `LOAD_GIT_BRANCHES` + `LOAD_GIT_WORKTREES` on every open with a sequence guard, inline notices for every refusal, toast + `REFRESH_GIT_STATUS` + close on success); `statusBar.js` wires it with mutual exclusion against the agents hover menu. `status-bar.css` holds the styles; the popover clears the dock for free because `#status-bar` is a fixed z-index 500 stacking context.
Main-side fixes the picker would otherwise trip over: `loadBranches` now returns `time` (`%(committerdate:unix)`), `remotes` and per-remote-row `remote`/`shortName` via the pure `src/main/gitBranchRefs.js` (`parseBranchLine`, `splitRemoteRef` longest-remote-first); `switchBranch` checks `refs/heads/` first, otherwise tracks any remote (`checkout -b <short> --track <remote>/<short>`, or the local twin) and reads the result from `--show-current`; both it and `createBranch` run through `execGitArgs` (execFile, no shell) and `createBranch` rejects names failing the shared `src/shared/gitRefNames.isValidBranchName`, which is stricter than git (shell metacharacters banned). IPC channels and payloads unchanged — the GitHub view got the multi-remote fix for free, and `ipcChannels.js` (in another spec's in-flight footprint) was never touched.
Rejected: a dock tab (checkout is transient; the dock shows one tab and would evict Activity/Decisions); alphabetical order; letting git refuse worktree-held branches instead of dimming them up front; an `isRemote` flag in the IPC payload; a `check-ref-format` subprocess per keystroke; splitting remote refs on the first `/` in the renderer; keeping shell-string `exec` for the touched commands.
Rules established: opening the picker runs reads only, never `git fetch`; branch names never meet a shell — new mutating git calls use `execGitArgs`; a remote row without a `shortName` is shown, not guessed away; one popover in the bar at a time; the status bar's indicator repaints only from `GIT_STATUS_DATA`, never by hand. The running-app pass (open, filter, switch, dirty tree, worktree row, Escape, dock open, both themes) was not done during the run — no DOM harness — and is the user's next step.
